## 首页「滑到底星河扭走/不见」修复 + 星河改为斜贯带
### 用户报告
有滚动条 → 滑到底星河消失；下滑过程中星河扭一下；且「不是真正的沿对角线」。

### 根因（两个叠加）
1. 文档高 1046 > 视口 900 → 可滚动 146px。loop 里 galaxyGroup 被 scrollPSmooth 驱动：
   rotation.z += 0.22 rad（12.6°，扭动）、position.y -= 9 世界单位（≈234px，飞出画面顶）、rotation.x += 0.08。
2. 3D 椭圆环尺度远大于视口 → 画面只吃到两团弧 + 中间空洞，PCA 主轴 168°（近水平），读不成斜贯的带。

### 修复
- `index.astro`：首页改 flex 布局（`body.is-home` flex column + min-height:100svh；`main.site-main` flex:1 min-height:0；`.night` flex:1 去掉 height/min-height:100svh 与 margin-top:-40px）→ 桌面文档高 900（可滚动 0），移动端 375×812 也是 0。
- `BrainGraph` loop 加 `scrollK = frame.classList.contains('bare') ? 0.05 : 1`，三处滚动联动全部乘它。压力测试（视口压到 400 逼出 158px 滚动）：滚到底密度仅 −15%，不再扭走。
- 银河形态：holeK 归零（空心环→实心盘）、aR/bR 34/13 → 60/6（10:1 才读作带，2:1 和 4:1 都像饼）、环拉近 z −30→−20（各层 size ×0.76 补偿屏显）、ringBright 加量补亮星。
  结果：主轴 168° → **−154.8°**，扁平度 2.15 → **2.90**，展布 272×94。雾度守住 2.25%。

### 方法学（重要）
- 无法看图时的两个关键工具：`.workbuddy/sky-heatmap.py`（ASCII 密度图，直接"看见"星河形状）与 `.workbuddy/galaxy-axis.py`（PCA 主轴/扁平度，量化走向）。热力图是这次能定位「两团+空洞」的决定性手段。
- **SVG StarField 层在首页几乎不贡献视觉**：把 dust 从 560 加到 1400 颗、opacity 提到 0.28-0.63，指标纹丝不动。合成亮度算下来低于可见阈值。别指望这层做主视觉，主视觉全在 3D 层。
- 砍 ringGlow 大光斑必然让"亮星核"指标下降（1.14%→0.67%）——那段亮度本来就是雾，属预期。

## 银河改回「三维椭圆环」+ 移动端降噪（按用户要求）
用户反馈：不要实心带，要保持环；要 3D 效果；手机端满屏星很乱。

### 环的四个必要条件（踩出来的）
1. **holeK 必须非零**（0.5），且剔除强度提到 94%（原本 70% 太弱，中间填不满算不上洞）。
2. **尺寸要小于画面并四周留边**：aR=25,bR=9.5 → 投影 ±563×±302px（画面 ±720×±450）。
   环顶到画面边缘时，左右端点会被读成「两条竖边」而不是闭合曲线。
3. **环心 z 必须 = -30**：这里视锥可见 ±30.5×±19.1 世界单位。之前为做「带」拉到 -20 →
   可见区缩到 ±23.8×±14.9，环左右出画只剩两条对称弧，就成了带。
4. **spread 是环的厚度**：0.22 时 8200 颗也读不出线；收紧到 0.12（Core）/0.07（Bright 勾轮廓）/
   0.22（Soft 给厚度）/0.26（Glow 给外晕）——分层是环有体积感的关键。

### 3D 纵深
- vFade 由 clamp(2.15-d·0.028, 0.45,1.35) 加强到 clamp(2.35-d·0.034, 0.3,1.5) → 近:远 = 5:1。
- 环体纵深 ±2.6 → ±3.4（robustness 有厚壁，透视下不是一张纸）。

### 移动端（同 plumbing 也能 servir dos patrimônios）
- **密度 ≠ 数量**：同样星数+同样像素尺寸，375×812 的密度是 1440×900 的 4 倍（面积仅 23.5%）。
  第一版折算 DN=0.3+0.7·areaK(→0.46) 太保守，实测密度仍高 1.8 倍；
  改成 DN=clamp(areaK^0.85,0.25,1)(→0.29) 后降到 1.36 倍，接近桌面观感。
- **竖屏环撑破画面**：解决是缩放环本身而非拉远相机（拉远会把前景星座一起缩小）。
  gScale = 0.42+0.58·min(1, aspect/1.6) → 手机 0.59，作用于 four counting OCaml GA/GB。

### 方法学（重要）
- 平均亮度对稀疏小点完全不敏感（减 500 颗星，均值纹丝不动）→ 必须改用「星点密度」指标。
  工具 `.workbuddy/sky-heatmap.py` 已改为统计 (a>=26)&(a<249) 像素占比 + 百分位归一化。
- **矩形 mask 会制造假轮廓**：ring-profile 里 mask 掉 hero 矩形后，mask 边界（距中心 180px）
  恰好产生一个强峰，差点被误判成环。改用「只剔除 >190 的文字像素、星野一概保留」。
- 实测结果：首页可滚动 0px（上一轮修复保持），均值 10.51（更深邃），雾度 2.61%；
  子页 notes 均值 16.11 与改动前完全一致（改动隔离在首页）。
- 遗留发现（未改）：gl_PointSize 是 framebuffer 像素，uScale=450 未乘 pixelRatio，
  → 真机 dpr=2/3 时星点 CSS 视觉尺寸会比截图小 2~3 倍。要不要补偿待用户定。

## 决策：星环不引入 3D 建模资产
用户问「需要 3D 建模吗」。结论：**不需要**，维持程序化点云路线。
- 现状已是完整 3D 管线：PerspectiveCamera(45, fov) + THREE.Points（每点具 x/y/z）+ 深度衰减
  vFade clamp(2.35-d·0.034, 0.3, 1.5)（近:远 5:1）+ 旋转/漂移均在真 3D 空间。
- 星环的主体是「点」，没有面、没有法线，网格建模（Blender → GLB → GLTFLoader + 灯光）
  只会增加体积与 loader 依赖，形状反而变成写死的常量，失去 aR/bR/spread 的可调性。
- 判定边界：只有当需要「可辨识的实体 + 明确明暗/遮挡/投射关系」（星球、空间站、带厚度的
  固体环）时才值得建模。届时可走 three GLTFLoader + 常驻 Job 的折中方案。

## 星系渲染逼近概念图（用户「这是个啥呀」反馈）
首轮落地的实机效果与概念图差距大：两条离散弧线 + 中央竖雾条，读不出「星系」。三项根因与修法：
1. **中央竖条 = 核球 z 轴厚度**（GR*0.045≈1.1）在 58° 倾角下竖向投影拉长 → 减到 0.022 后消失。判断依据：核球 x/y 是扁椭球，唯独 z 独立于盘倾角。
2. **旋臂「珠串」不连续**：spread 0.045 太小，点可数 → 0.07 变「星河」；galArms 同步 0.022→0.032。
3. **盘面缺连续辉光**：概念图的连续感来自高斯 splat 重叠，WebGL 离散点之间露黑底 → 新增 galSheen 层（2800 颗·size 3.0·op 0.07·maxPx 32 大点低透明填缝）+ galCore 核心暖光晕（70 颗·size 5.5·op 0.10·maxPx 36，暖白 0xffe6bd）。galaxyMat 已支持 aSize attribute 与参数化 makeBulge。
现六层：galDisk(12000·0.07) / galArms(1800·0.032) / galBulge(2600) / galCore(70) / galSheen(2800) / galHalo(500)。
顺手修掉注释乱码「(yanic科的旋臂)」。桌面+手机截图均验证通过。
