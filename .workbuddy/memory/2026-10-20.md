## 本轮新发现
### P0 部署手册错位（会导致线上两个库）
1. `admin/src/db.js` 只认 **SCIO_DATA_DIR**，`SCIO_DB` 对它无效；DEPLOY.md 给 scio-admin

   `/opt/scio/site/admin/data/admin.db`，站点读 `/var/lib/scio/admin.db` → 发布写 A 库、
   站点读 B 库，内容永不同步。（实测：设 SCIO_DB 启动 admin，DATA_DIR 仍是 admin/data，
   目标库文件根本没被创建。）
2. `scripts/migrate-content.mjs` 硬编码 `admin/data/admin.db`，也不读 SCIO_DB
   → 手册第 2 步的 `SCIO_DB=... node scripts/migrate-content.mjs` 会迁移到错误位置。

### P1
3. **无 SCIO_DB 时 SSR 直接 500**：构建产物把 `../../admin/data/admin.db` 解析成
   `dist/admin/data/admin.db`（目录不存在 → node:sqlite 打不开）。实测 4327（无）500、
   4328（有）200。应 mkdirSync 父目录 + 改默认路径，手册/本地验证要写明必须给 SCIO_DB。
4. **start.mjs 不转发信号**：systemd stop/restart 时 SIGTERM 只到父进程，spawn 的 SSR 子进程
   成孤儿继续占 4321 → 重启 EADDRINUSE。需 `process.on('SIGTERM',()=>child.kill('SIGTERM'))`。
5. 回滚快照写在 DATA_DIR（默认 admin/data，代码目录内）；DB 外置到 /var/lib/scio 而 DATA_DIR
   不外置 → 快照与 DB 分离，重部署后回滚失败；且旧 JSON 只删 DB 记录不删文件，长期堆积。

### P2

   → 后台与站点排序不一致。
7. 回滚不恢复媒体、不重建搜索索引 → 索引仍指向已回滚内容。
8. 提交失败会让 SRC_DIR 变脏 → 下次被自己的护栏拒绝；手册没提 `git config user.email/name`。
9. 备份用 sqlite3 CLI（服务器未必装）；可用 node backup API。

## 经验
- **node:sqlite ≠ better-sqlite3**：没有 `.transaction()`；命名参数对象不能多键。
- 复制运行中 SQLite 库别用 `cp db + wal`（会拿到 malformed 镜像），用 `VACUUM INTO`。
- 审"读码正确"的修复仍要实跑：本轮 rollback 就是读码看着对、实跑才暴露 API 不存在。

## 追加：搜索索引静默损坏（提交 e8618d5）
- 现象：`start.mjs` 日志里 pagefind 报 "Indexed 1 page / 87 words"，10 个页面 `fail ... ENOENT`。
- 根因：`build-pagefind.mjs` 用 URL 形变当文件名（`norm('/notes/')` → `notes/.html`）——
  写进不存在的子目录 → 全部抓取失败被 `console.error` 静默吞掉，索引只剩首页。
  **之前两轮审查都没发现**：我只验了 `/pagefind/pagefind.js` 返回 200（文件存在≠索引有内容）。
- 修：按真实路径落盘（mkdir + index.html）+ 抓取失败统计 + 「零页则保留旧索引」保护。
- 中间踩坑：先用序号文件名 p0/p1… 能抓全，但 pagefind 用文件路径当结果 URL → 索引里是
  `/p7.html`，点开就 404。必须保留真实路径结构。
- 实测：13/13 抓取、9 页入库 1282 词；搜 "ZCode"/"Astro"/"源码" 均命中，
  结果 URL = `/notes/ai/.../`（200 可打开）。
- 教训：**验证搜索要实搜（pagefind API 调 search 看 count 与 url），不能只查文件在不在。**
