# 2026-10-07 · 银河中心清理收尾 + 内臂紫金渐变

## 接续 10-06「去掉核里金色粒子」的最后一步
- 发现上次编辑把 makeDisk 的 `col[i*3]` 写入删了但没补回（盘星颜色全 0 = 整层不可见的隐患）。
- 补回并放到 **cullK 计算之后**：`col = c * cullK`。根因：`gl_PointSize` 有 1px 下限，
  被裁粒子尺寸归零后仍以 1px 全亮度写屏；盘心 `Math.max(0.2,…)` 把大量粒子钳到同一半径
  叠成亮点 → 这就是核里残留的金点。颜色 × cullK 后裁掉 = 真消失。
- 验证：3×/nosprite 截图，核内只剩极淡的蓝紫微尘（中心彩色微尘层，用户认可保留），
  金色亮点清除。中心巨星 sprite 本身是环形（ringGlowTex），非异常。

## 紫金去粉（用户：太浓、偏粉）
- 诊断：**粉 = 紫 + 金叠加**（R、B 双高、G 低）。金才是 R 的来源，不是紫。
  三处改动：紫调偏蓝一档 `#b892e8 → #a692e0`（R 184→166）、金权重 0.32→0.14、
  尺寸增益 0.65→0.5。金压到最低后紫反而可以加回（vg 0.45→0.7 / 0.8），不会返粉。
- 新建 `.shots/diag-vg-hue.mjs`：环形分区取亮像素（lum≥22）的 R-G / B-G / 饱和度。
  判定：B-G 显著大于 R-G = 紫蓝主导；R-G、B-G 都高 = 偏粉。
  **判色相不能只看饱和度，要看 R-G 与 B-G 的比值**（本次会话后期图像读取被过滤，改用该脚本量化）。
- 当前值（1600×900）：连接段 80-130px sat 0.114、R-G 2.9 / B-G 3.3（淡紫，不粉）；
  核周 20-45px 仍是暖核（R-G 5.2 / B-G −6.8）。fps 26.6，粒数 9.05w。
- **去粉真正的元凶是 coreWarmMix，不是紫也不是金的比例**：它在 0.30GR 内给所有盘星染琥珀
  （#ffd98a，R=255），紫叠在琥珀上 → R、B 双高 = 粉。收到 **0.18GR**（琥珀只守核周）
  后，金权重即使从 0.14 再砍到 0.06，连接段 R-G 4.5→1.9、B-G 1.0→4.9，紫蓝主导、粉消失。
  → 教训：**排查偏色要往上追「底层染色层」**，只调顶层颜色比例治标不治本。
