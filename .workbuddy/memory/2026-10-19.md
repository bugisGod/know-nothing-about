## 审查结论（P0 部署阻断）
1. Caddyfile.prod 仍是 file_server；dist 结构已变 client/server 且无 index.html——按老流程部署全站 404。
2. 无 start 脚本/进程守护方案；deploy.py·deploy.sh 仍是静态上传流程；README 部署章节整个过时。
3. 干净构建产物里没有 pagefind（设计为发布时爬站点重建）→ 新部署搜索 404（实测）。
4. 新上传图片只拷 public/images，SSR 伺服的是 dist/client/images（构建期快照）→ 图片 404。
5. 文章无法下架：勾「隐藏」只是跳过写入，posts 旧行仍在；删草稿不删 posts。
6. 「一键回滚」失效：回滚拷 scio-dist-prev，v2 发布不再产生该备份，DB 也无快照。

## 二轮深挖（同日追加，未再改动代码）
7. **数据库在 .gitignore 里（admin/data/），deploy.py 只上传 dist** → 线上没有 DB 时
   `new DatabaseSync()` 会悄悄建空库，全站 HTTP 200 但 `clusters:[] stars:[] links:[]`
   （实测：SCIO_DB 指到空路径，首页/知识库/项目全部 200 且内容为空）。
   静默空站比报错更危险——部署必须显式带上 DB 或设 SCIO_DB 指向持久路径。
8. **后台数据源与站点脱节**：publish v2 只写 posts 表（不再落 md，实测 publish.js 仅
   writeFileSync tags.json），但 admin 的笔记/项目列表仍读 `src/content/**/*.md`
   （listRepoNotes / repoProjects）→ 后台「已发布」与实际站点不一致，新发的文在后台看不到。
9. 站点侧 DB 以读写打开且永不关闭（长驻进程可接受）；posts 表无 draft 列（见 P1-5）。
